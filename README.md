# Learning Development Hub

A centralized workspace for planning, designing, developing, testing, and maintaining digital learning experiences and training solutions.

## Purpose

This repository brings learning design and development resources together, including:

- Instructional design plans, course outlines, and storyboards
- Articulate Storyline 360 and Rise 360 project resources
- SCORM learning packages and validation resources
- HTML, CSS, and JavaScript learning components
- Assessments, question banks, and practical exercises
- Approved multimedia assets and reusable templates
- Technical documentation, quality assurance, and deployment guidance

## Technology and platforms

| Technology or platform | Intended use |
|---|---|
| Articulate Storyline 360 | Interactive eLearning authoring |
| Articulate Rise 360 | Responsive course authoring |
| HTML5, CSS, JavaScript | Web-based learning and reusable interactions |
| SCORM 1.2 / SCORM 2004 | LMS-compatible course delivery |
| TrainCaster LMS | Learning management and course delivery |
| Git and GitHub | Version control and collaboration |

Tools and standards may vary by project. Document project-specific requirements in the relevant project folder.

## Repository structure

The numbered folders below are the planned top-level organization. Add a folder when it contains actual project material; Git does not track empty folders.

| Folder | Purpose |
|---|---|
| `01_Project-Management/` | Project briefs, registers, roadmaps, and change logs |
| `02_Instructional-Design/` | Learning objectives, outlines, storyboards, scripts, and assessment plans |
| `03_Course-Development/` | Storyline, Rise, SCORM, HTML course, and interactive module source projects |
| `04_Reusable-Assets/` | Approved images, icons, audio, video, illustrations, and templates |
| `05_Assessments/` | Quizzes, question banks, practical assessments, answer keys, and rubrics |
| `06_Web-Components/` | Reusable HTML, CSS, JavaScript, and interface components |
| `07_Documentation/` | Standard operating procedures, user guides, and technical documentation |
| `08_Testing-and-QA/` | Test plans, accessibility checks, SCORM validation, and bug reports |
| `09_Deployment/` | LMS deployment instructions, release materials, and approved packages |
| `10_Archive/` | Retired projects and historical materials retained for reference |

## Working principles

1. Keep editable source files separate from published or generated output.
2. Use clear, consistent file and folder names.
3. Document project purpose, audience, learning objectives, dependencies, and status.
4. Reuse approved components and templates where practical.
5. Test interactions, accessibility, and LMS behavior before release.
6. Keep credentials, personal data, and confidential company or client information out of this repository unless explicitly authorized and appropriately protected.
7. Record significant changes in `CHANGELOG.md`.

## Getting started

1. Review this README and `CONTRIBUTING.md`.
2. Create or select the relevant project folder.
3. Add a project-level README describing its purpose, owner, status, tools, and instructions.
4. Keep source files and approved assets together, and exclude temporary build files.
5. Record meaningful updates in `CHANGELOG.md`.
